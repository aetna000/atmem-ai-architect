# Terraform apply emulator

Owner request (2026-11-16): a Terraform emulator for AWS, Google Cloud, Azure and IBM. Start with AWS; make it comprehensive.

## Outcome

Run the complete Terraform lifecycle of a generated project — or any Terraform directory — with the real Terraform CLI and real provider plugin against a cloud API on loopback. No cloud account, credentials or spend. This closes the boundary recorded in 022: "Terraform apply is not run".

## Capability and invariant

- **Capability:** provider-neutral lifecycle engine: init → validate → plan → apply → independent API read-back → convergence plan → destroy-protection proof → destroy → leak check.
- **Invariant:** only the cloud endpoint is replaced. Terraform, the provider, the configuration and its dependency graph are the real ones. The source directory is never modified; every input file is hashed into the report.
- **Applicability:** any root module whose providers all belong to one family with a registered backend, plus local-only providers (`random`, `null`, `time`, `tls`, `archive`, `local`, `external`).
- **Interfaces:** CLI `server/terraform_emulator.py --dir`; job API `POST /api/terraform/emulate` + `GET /api/terraform/emulate/{jobId}`; report `kind: terraform-apply-emulation`, version 1.
- **Limits:** see Evidence boundaries.

## Statuses

| Status | Meaning |
| --- | --- |
| `passed` | Every stage passed. Never inferred from a partial run. |
| `failed` | Terraform, read-back, convergence or teardown failed for a reason not attributed to the emulator. |
| `unsupported` | The backend does not implement a required API operation. Not a pass and not a configuration failure. |
| `blocked` | Unfinished generator work, or a required input has no synthetic rule and was not supplied. |
| `unavailable` | Runtime, Terraform or a backend for this provider family is not installed or not implemented. |

## Requirements

1. Redirect every service endpoint of the provider without editing the configuration. Fail closed: no inherited credentials, profiles or proxies; HTTPS to a real endpoint cannot connect.
2. Record every provider API call (service, operation, status). An unimplemented or crashing emulator operation is answered once with a non-retryable error and reported as a gap.
3. Read applied resources back through an independent SDK client and compare with Terraform state. Types without a verifier are labelled provider-refresh-only.
4. Require a zero-change second plan.
5. Prove `lifecycle.prevent_destroy` blocks teardown before lifting it in the private workspace only.
6. Destroy, then query service inventories directly; nothing may remain.
7. Synthesize only destination inputs with an explicit rule (account, region, review approval, referenced principals, alert topics). Otherwise block and name the missing inputs.
8. Emulator defects are repaired by version-scoped, documented adapters listed in every report — never by weakening the configuration or forcing success.
9. Coverage is measured by a fixture corpus per service family and published per resource type. Types outside the corpus are unmeasured, not assumed.
10. Azure, Google Cloud and IBM use the same engine and report. Until a backend exists they return `unavailable`.

## Evidence boundaries

Emulated responses are not the cloud. IAM/resource policies are stored, not enforced. Quotas, limits, timing, availability and pricing are not emulated. Compute is registered through the API; its code is not executed by this check (022 covers handler behavior). A pass is not an account plan or a deployment. Local process isolation is not a multi-tenant sandbox; hosting needs the isolation listed in 022.

## Acceptance

- Seven archived AWS example projects run through the current generator; results recorded per project.
- Corpus coverage file `docs/terraform-emulator-aws-coverage.json` regenerated by `scripts/qualify-terraform-emulator.py --write`.
- Positive and counterexample lifecycle tests: a passing fixture; a configuration the API rejects fails without being called an emulator gap and still tears down cleanly.
- Transfer: the same engine runs generated JSON projects and hand-written HCL fixtures across unrelated service families.
