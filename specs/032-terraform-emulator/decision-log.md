# Decisions and observed gaps — 2026-11-16/17

- Owner requested a Terraform emulator for AWS, Google Cloud, Azure and IBM, AWS first and comprehensive. Interpreted as executing the real Terraform lifecycle against local cloud APIs, because 022 records "Terraform apply is not run" as the open boundary. Writing a cloud API emulator from scratch was rejected: the provider's wire behavior is the thing under test.
- Backend: Moto 5.2.5 in server mode, already the pinned emulation dependency. It runs in-process inside an isolated runtime (`.local/terraform-emulator-runtime`, hash-locked) because server mode needs Flask and the server environment must not change. No Docker daemon is needed.
- Redirection uses the provider's own `AWS_ENDPOINT_URL` environment contract, so generated files stay byte-identical and aliased or module-level provider blocks are covered. An explicit `endpoints` or `profile` in a configuration would override it and is reported by Terraform, not hidden.
- Observed: the provider calls S3 Control at `<account>.<host>`, which does not resolve for a loopback address. Plain-HTTP requests to non-loopback names are proxied to the emulator; HTTPS goes to a closed port. This also makes any missed endpoint fail closed.
- Observed: provider plugin sockets exceed the Unix path limit under a deep temporary directory. Workspaces use a short `/tmp/tfe-*` root.
- Observed: Moto drops tags sent inside `CreateBucketConfiguration`; the provider then reports false drift on every tagged bucket. Added adapter `moto-s3-create-bucket-tags-v1`, scoped to the exact successful CreateBucket request. No upstream issue or PR has been submitted or claimed.
- Observed: generated buckets carry `prevent_destroy`, so teardown failed by design. The emulator first proves the protection blocks a destroy plan, then lifts it with an override file in the private workspace only. Protected resources inside child modules are refused rather than bypassed.
- Observed: the AWS SDK retries 5xx for minutes, so an unimplemented Moto operation stalled runs. Emulator gaps and emulator crashes are now answered once as non-retryable errors (`EmulatorNotImplemented`, `EmulatorInternalError`) in the service's wire protocol and classified `unsupported`.
- The generated review gate defaults to closed. Emulation sets `review_approved = true` inside its private workspace as an explicit rehearsal input; this is not a deployment approval and is listed under `inputs` as synthetic.
- Leak detection queries service inventory APIs rather than Moto internals, so it stays independent of the emulator's implementation.
- Azure, Google Cloud and IBM are registered provider families with no backend. They return `unavailable`; nothing is claimed for them.
- Observed: the provider's CloudWatch client uses smithy rpc-v2-cbor, which Moto server mode does not route; every project with an alarm stalled. Added a shape-aware CBOR/JSON bridge driven by the pinned botocore model.
- Observed and repaired in Moto: SQS RedriveAllowPolicy unreadable, RedrivePolicy re-serialized, queue Policy cleared by unrelated attribute updates; conditional S3 bucket-policy statements enforced unconditionally; alias-qualified event source mappings rewritten to version ARNs.
- Terraform commands run in their own process group. A provider waiter that never completes is cut off at the time limit, the resources still creating are named, and teardown still runs.
- Required inputs without a synthetic rule take the literal values of the module's own `tests/*.tftest.hcl` variables block (the generator's qualification inputs), labelled `module-test`.
- Owner direction (2026-11-17): where the open-source base is unsupported, build the engine; aim for the best AWS emulator. Introduced AtMem-built engines that answer before Moto and are named in every report. First engines: CloudFront (distributions, tags, three policy families, managed catalog), Step Functions definition validation and version listing, Cognito DeleteResourceServer.
- Observed: the provider dereferences members real CloudFront always returns (for example OriginGroups). The engine therefore applies CloudFront's stored-configuration defaults instead of echoing the request; sent values are never changed.
- Owner request (2026-11-17): a clickable Board card that starts emulation and animates the diagram. The worker streams Terraform's per-resource events; blocks change state only on those events and on read-back results.
