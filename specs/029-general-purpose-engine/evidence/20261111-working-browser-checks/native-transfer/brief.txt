This is an explicit local native/browser-tool qualification fixture, not a cloud project or an architecture holdout. Build a small runnable web tool for volunteers to preview a shift note before they copy it. No publishing, account connections, persistent storage or cloud services.

Use a real local HTTP service and browser page. The page sends POST /api/preview with {"note": text}; the server returns {"preview": text} with a plain-text preview. Reject empty or nonstring notes, extra fields and notes over 2000 characters. The person can clear the entered note and preview. A slow in-flight response must never restore cleared content. Make server failures visible, keep the page usable for a later successful request, render text safely, and do not persist entered notes or previews. Simple build/run/test instructions and pinned runtime/test dependency information belong in the handoff. Choose routine details yourself.

Use the offered atmem_check_working tool with the server-registered node-browser-tests validator to execute the actual emitted application and browser tests in its isolated runtime. Read the complete check report, repair real failures, and check a new checkpoint after edits. Tests should run an actual loopback HTTP server and Chromium with its sandbox enabled, including normal preview, rejected input, server failure/recovery, clear and an in-flight clear race. The model worker cannot bind a host server or use Docker; the isolated validator permits its private loopback. The catalog describes its supplied browser module environment path. No network installs or account access are available. Preserve backend-supplied pinned files. Generated tests and a local pass are component evidence, not independent system acceptance.
