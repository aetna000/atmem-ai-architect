# Pinned runtime facts and public dependency closure

Reusable capability: register operator-observed immutable validator facts and a bounded, hash-pinned public artifact mirror. New engineering workspaces receive the complete public catalog; the native worker can read the explicitly approved mirror, while generated projects must carry their chosen dependency sources, licenses, pins and portable build. No resolver, installation, code import or network access occurs in the backend catalog loader. Runtime facts are bound to the actual image/platform/bootstrap/environment/isolation profile and successful empty-source probe; unknown metadata remains unknown. Old sessions and contracts without receipts remain compatible.

Interfaces: optional validator `runtimeReceipt: {path, sha256}` and optional toolchain `dependencyMirror` directory within registered read roots. The backend verifies all bytes before workspace creation and pins `atmem-tools/dependencies.json`. Runtime public metadata contains no operator host paths. Changed mirror bytes or observation bindings require operator review/restart, never silent adaptation.

Validation: all **381 server tests pass**, no skips (`server-tests.log`). Three actual isolated runtime observations identify Python 3.13.18 AMD64, Lambda Python 3.12.16 ARM64 with baked boto3/botocore 1.42.97, and Node 26.13.0/Playwright 1.64.1/Chromium 156.0.8078.80. No image pulls or cloud calls. Null package metadata is not proof of module nonexistence.

Seven public exact-version wheels have source/metadata hashes and explicit Linux AMD64/ARM64 Python dependency closure (`dependency-catalog.json`, `dependency-preparation.json`). Qualified boto3/botocore 1.43.123 source subset imports and passes **13 checks on each Python runtime**, including actual synthetic signed HTTP for retention success modes, denial/throttle/internal failure and one-attempt timeout configuration (`sdk/`). The complete wheel library is not qualified: botocore data covers only Bedrock and Bedrock Runtime. An initial evaluator incorrectly demanded a null input shape instead of accepting an empty SDK structure; its failure is retained separately and the corrected oracle preserves the GET/no-input requirement.

Transfer and counterexample: actual native command sandbox reads/copies/extracts the approved jmespath wheel and executes an independent classroom/weather JSON query; writes to the mirror and reads of an unregistered synthetic host file are denied (`worker-boundary.json`). Component tests additionally reject changed bytes, extra entries, links, duplicate/traversing names, private URL credentials and wrong receipt bindings; metadata admits different language artifacts without importing code.

Reviewed knowledge adds a provider-scoped account-retention read contract, with exact SDK/local evidence and limits. This supplies available machine checks rather than substituting a manual attestation. It does not qualify a generated application's gate. Existing exports remain unchanged; fresh original AWS generation and independent frozen-criteria assessment follow. Original acceptance remains **0/28**, released candidates **0/10**, measured quality unknown. No real account, deployment, hosted tenant isolation, all-SDK/CRT or atomic provider-drift proof.

Manual test: register reviewed runtime receipt pins and a public flat mirror using the evaluation preparation scripts; start a fresh Build project, inspect its pinned catalog and full runtime evidence, and require its portable dependency/build tests. Mutate a copied artifact and verify admission refuses it. Do not change shared approved artifacts during a run.

No migration or cloud action is involved. These optional registrations do not change old native tool definitions on resume.
