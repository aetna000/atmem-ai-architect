# Native engineering access to shared application runtime

## Engine repair

The browser generator could emit shared approval/API source, but fresh native
engineering sessions received only prose describing those modules. Supply the same
production source and provider locks as optional pinned backend inputs, without
requiring a domain recipe or making a client choose machine IDs. The native agent
can inspect applicability, materialize source offline and write real domain stages,
API/worker/operator entrypoints, native resources and connected tests around it.

`src/workflow-runtime-inventory.mjs` owns the production module inventory. The build
embeds those exact sources and current reviewed four-provider dependency resolutions
in `server/engineering_assets/application-runtime.json`. Fresh sessions pin that
catalogue and `atmem-tools/materialize-runtime.py` with the existing delivery inputs.
The portable helper copies only source/locks/provenance into a fresh public relative
application directory. It installs/executes nothing, imports no application code,
reads no credentials and performs no SQL/model/cloud request. Reject unknown
providers, corrupt source digests, duplicate JSON fields, unsafe/reserved paths,
existing output and linked ancestors before creating output. Failed partial copies
require a fresh destination. The manifest identifies source bytes, not correctness
or a cryptographic review/deployment attestation.

The optional SDK contains shared HTTP, native identity, SQL/queue, approvals,
bounded child stages and normalized TLS integration. It contains no invoice domain
processor or synthetic tests. It does not implement arbitrary requirements or
supply provider resources, operating policy or identity/membership decisions.
The native engineer remains responsible for choosing an appropriate design,
implementing business/authorization policy and qualifying the connected system.
API exports retain their prior smaller module set; native workers additionally
receive the process boundary and AWS model adapter. Browser/native source and
provider dependency pins are checked for equality.

## Selected Python environment repair

A second executable symlink loses Python's virtual-environment prefix. Resolving
an operator-selected venv executable to its base binary also loses its dependencies.
Preserve the original selected venv path and use a literal, argument-preserving
launcher for that case. Validate both the executable and environment read roots in
the backend; expose no additional home/credential trees. Ordinary standalone tools
retain existing aliases. The exported prepare helper makes the same registration
from receiving-engineer choices, accepts its exact existing launcher and refuses
unknown files/links. Spaces and shell quotes are covered by an actual environment
with an import canary. Existing live/resumed workspaces retain original pins.
