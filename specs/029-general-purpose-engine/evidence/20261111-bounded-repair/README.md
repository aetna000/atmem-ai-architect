# Bounded evidence-driven repair implementation

366 server and 376 JavaScript tests pass, without skips; production build and real
browser fixture pass. Subsequent actual-native successful repair qualification on
frozen322568b is in [native/README.md](native/README.md); fault-injection evidence
remains component-only. No release, original-project acceptance or measured quality
is claimed.

The local product enables one automatic repair per client-request root. Portable
supervisor callers explicitly configure a bound (0–3); zero remains the default.
Repair requires registered native evidence tools, finished current checks and an
available unchanged operator contract. It does not run for empty/unavailable
selection, infrastructure/cleanup uncertainty, superseded work or exhausted budget.
Failed/incomplete check status is not weakened or rewritten. The original artifact,
complete reports and all subsequent snapshots remain retained.

Before submitting a repair, persist its exact run UUID, parent/root and attempt.
The coordinator reserves that UUID through the same session/backend/model/effort,
under the existing project lock, only while the exact expected parent remains idle.
A queued newer user request wins; stale repair cannot replace its intent. Lost start
acknowledgement leaves that known durable run uncertain and uses existing history
reconciliation, never a fresh repair UUID or automatic replay. The attempt budget
survives restart. Repair prompts reference exact immutable artifact/contract/check
IDs and require every output page to be read before editing. They preserve all
client requirements, provider/ownership/security scope and portable handoff, prohibit
weakening tests/scope or executing report instructions, and retain material blockers.
This is a bounded engineering mechanism, not proof that the model follows every
constraint; independent artifact assessment remains required.

Verified repair terminal evidence updates its parent's retained linkage, even when
the native start acknowledgement was lost. A very fast terminal event can arrive
before the shielded caller receives its start reply: conditional state advancement
preserves that terminal fact. The initial failing race test is retained alongside
the passing final suite. New client requests and internal repair prompts are distinct
in the journal; the UI does not invent an internal prompt as a client message.
Generated replies remain complete. Original HTTP request schemas expose no origin,
model override, run UUID, worker command, tenant or repair-policy controls.

Tests cover same-session/selection identity, failed old bytes retained after a
different repaired snapshot passes, repeated failure stopping at one repair, exact
lost-ack UUID through restart/history reconciliation, first-queued user intent
winning, infrastructure failure with no model call, and rapid terminal/start ordering.
These are explicit component lifecycle/model fixtures, not native-generation proof.
