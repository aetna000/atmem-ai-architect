# OpenAI voice interface preview

Reusable invariant: audio input/output is a separate modality interface, not a replacement architecture model or a route around requirement/ownership/review controls. Browser uses the backend API; no native CLI credentials/host paths. A submitted transcript enters the ordinary selected Architect path, and only its written reply is supplied to an out-of-band audio response with no tools. Personal/project memory is unchanged.

Implementation: current official Realtime WebRTC workflow, fixed reviewed audio/transcription models and marin voice. Backend returns only a60-second ephemeral credential, sanitizes failures and follows no upstream redirects. Local session auth/origin checks and strict empty session request prevent model/key/endpoint overrides. Dedicated voice-key setup stores only server-memory state and cannot replace the Architect provider credentials. Existing server OpenAI credentials may be reused when no dedicated voice key exists. No keys/audio in project files, AtMem memory or browser localStorage. Short credential lifetime does not end an established voice session; explicit Stop and a20-minute client connection cap close its microphone/peer.

UI: one OpenAI voice launcher and status near the composer; settings reuse the existing dialog styling. Starting connects explicitly, then returns to chat. Default transcripts require Send; automatic sending is opt-in. Unsent drafts survive, committed turns retain order, duplicate/late events are ignored, uncertain/failed recognition pauses automatic sending and keeps recognized pending words for manual review. Project/chat unmount closes the session. Written replies stay authoritative. Permission/playback/setup failures have explicit text actions. Local Whisper dictation remains separately named, with no automatic browser-TTS fallback.

Validation:566 JS tests/no failures/skips;484 server tests pass; production build passes with the existing chunk warning. Eight controller tests and five backend tests cover auth/origin/overrides, ephemeral-only secrets, dedicated-key isolation, exact text/order/deduplication, pending draft retention, late permission results, interruption, playback retry and cleanup. Actual UI with synthetic API/WebRTC/audio verifies dedicated setup, unchanged gpt-6.1-sol/high Architect routing, manual/automatic turns, written-reply readout payload, unsent draft retention and Stop/late-event guards. Delivery and memory/review browser regressions pass. No real OpenAI request or owner project write in those fixtures.

Actual Chromium media/RTP/data-channel loopback passes with a virtual microphone, generated tone, explicit microphone/local-network-access test permissions, autoplay and loopback/mDNS fixture flags listed in webrtc-loopback.json. Both RTP directions and transcript transport are observed; microphone and peer stop. This is constrained local transport proof, not a human listening test or OpenAI service/account proof. Initial/default local ICE runs failed; the run without loopback flags remains failed and is retained. Do not present this as successful default browser networking. Fixtures bridge candidates between two full browser ICE agents; they do not qualify the public OpenAI endpoint.

Browser testing caught borrowed Window fetch/timer bindings that mocks missed; callbacks now use wrappers. The initial expanding chat card left unusable blank mobile space and was replaced with the established dialog without CSS changes. One review fixture stalled while scrolling; a stable-source retry passed without a product change, cause unqualified. All attempts/logs/screenshots remain under .local/external-artifacts/openai-voice/.
