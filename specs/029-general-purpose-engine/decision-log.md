# Decisions — general-purpose engine

## 2026-11-11 — Owner-directed correction of programme priority

The owner explicitly requires a generic expert engine, not 28 tailored projects,
and a comprehensive review before further feature expansion. The original 28-case
scope remains as diagnostics/regression. Unfamiliar combinations and uncoached real
user conversations become explicit acceptance dimensions. Preserve qualified work;
extract shared mechanisms and keep legitimate provider/domain adapters behind contracts.

## 2026-11-11 — Ten tangible release subgoals

The owner requests ten incremental improvements with runnable versions for manual
testing. Define ten dependency-ordered subgoals and candidate versions in plan.md.
Roadmap percentages are not measured quality. 95% quality remains a target requiring
a frozen rubric, independent evidence and critical-invariant gates. Documentation
alone is not a release. No remote publication or cloud deployment is authorized here.

## 2026-11-11 — Knowledge is layered, not scenario answers

In response to the owner's skills-versus-hardcode question: reviewed skills/practices
carry contextual judgment; deterministic contracts and reusable mechanisms enforce
invariants; provider adapters implement real cloud differences; independent tests
qualify combinations. Do not encode benchmark answers in production decision logic.
No model training is claimed. Apply the review's transfer criterion to both knowledge
and executable implementation, not just the choice of names.

## 2026-11-11 — Local emulation is the required acceptance boundary

Owner clarified: no real cloud deployment is needed; validate blocks and the complete
system through emulation. Require generated block, connection and end-to-end behavior,
with independent oracles and explicit mock/native limits. Do not treat account access
as a blocker to this local acceptance programme or inflate a local pass into cloud proof.
Initial cross-layer source review is complete; behavior/generalisation qualification
continues through the releases. Begin shared release-1 repairs, not specialized expansion.

## 2026-11-11 — Specialized native Codex is the engineering foundation

Owner explicitly wants the speed, intent following, strong model and skill/tool
workflow of a native Codex session, augmented with infrastructure expertise and
AtMem learning. The constrained graph-chat path is insufficient as the engineering
engine. Select the official local app-server integration; keep native base instructions
and skill execution, augment with reviewed domain guidance. Separate user conversation
from capable engineering work, preserve project intent and verify exact output.
Require same-model/effort paired native baseline and no silent cheaper fallback.
Local block/connection/system emulation and Terraform checks remain the acceptance
boundary; cloud deployment is outside scope. First release now includes a working
specialized session; protocol/metadata tests alone cannot satisfy that release.

## 2026-11-11 — Cloud web-app portability, not client-local Codex dependency

Owner explicitly requires later cloud web hosting. Codex is the first execution
adapter, not a requirement on the user's computer or the core project model. Use a
backend session service and isolated execution workers, portable project/skill/
artifact/evidence contracts and backend-owned authentication. The browser never
runs a CLI or receives model credentials. Local process transport is development
infrastructure; qualify a worker-service transport and hosted isolation before cloud
use. No cloud deployment is requested now.

## 2026-11-11 — One locally runnable and cloud-SaaS product; paywall deferred

Owner confirms both local operation and later cloud SaaS for paying users. Preserve
one engine/session/worker/artifact contract across deployment modes. Prepare the
isolation, authentication and usage/evidence boundaries now; defer Architect's own
paywall, billing and checkout implementation. This does not waive original evaluation
requirements for generated metered client systems. No hosted deployment is authorized.
