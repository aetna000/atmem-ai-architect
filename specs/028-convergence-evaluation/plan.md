# Fast convergence and trustworthy handoff evaluation

Owner authorized changing the UI, engine and method to achieve quality handoffs, and
requested 2 simple, 3 medium and 2 hard typical AI projects on each of 4 providers:
28 cases, iteratively evaluated and repaired. Ten meaningful user exchanges is a
pacing target for standard systems, with more allowed for genuine complexity.

The benchmark and rubric are frozen in benchmarks/convergence before the baseline.
Use the real Architect runtime, knowledge/skills and state/export code. Keep a
transcript per case, user facts/answers, exact source and artifact hashes, independent
checks and explicit failures. Unsupported application/connection generation counts as
failure, never as a successful smaller project. Separate architecture reasoning,
interaction burden and package/runtime quality. Do not deploy or claim deployment.

1. Finish and verify ownership, clear blocked-test guidance, accepted-setting prefill
   and rapid user intake. Preserve component-first work already in the workspace.
2. Build the live conversation driver and independent package assessment for all 28.
3. Run baseline, inspect failure clusters, and fix the engine/generator rather than
   exported projects or benchmark scope.
4. Rerun affected cases and the full matrix after structural changes. Add held-out
   variants for changed constraints, identity, retries, recovery and existing systems.
5. Retain failed and successful runs; report convergence and the exact qualified scope.

A coding-agent handoff needs concrete application, infrastructure, contracts, tests
and operations, not a generic checklist. Target attainment requires evidence, not the
agent declaring itself happy with the diagrams.
