# Public release 0.2.6 and client privacy

The owner authorized a stable release on main, with private client documents and
handoffs excluded from public source, examples, packages and history.

1. Preserve restricted documents and prior source history in private repositories.
2. Build a clean public source history without private ancestry or client examples.
3. Apply an external private policy to tracked source and recursive release archives.
4. Qualify the native drawing release, clean installation and the three-platform CI matrix.
5. Publish through the trusted npm workflow, verify exact registry bytes/latest,
   and retain the public release notes and verification evidence.

The reusable release boundary supports arbitrary private text patterns and binary
fingerprints. Nested documents are inspected without extracting archives. Synthetic
counterexamples cover private text, binary digests, paths, malformed archives and
escaping links; contained third-party timezone aliases remain supported.

Checks cannot revoke copies downloaded before privacy correction or classify unseen
confidential paraphrases and image text. The release is architecture software, not
deployment qualification of a client system.

Rollback: install a prior package while preserving the local data directory. Never
restore restricted history into the public remote. Original client artifacts remain
unchanged in private storage.
